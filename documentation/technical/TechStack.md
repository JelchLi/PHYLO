# Tech Stack

## Purpose

This document defines the technologies approved for the development of PHYLO.

The goal is to maintain a simple, consistent, and maintainable technology stack while allowing future growth.

---

# Core Technologies

## Astro

Astro is the main framework used to build the PHYLO platform.

It provides a component-based architecture while generating fast, static websites by default.

---

## HTML5

HTML is used to build semantic and accessible page structures.

Semantic elements should be preferred whenever possible.

---

## CSS3

CSS is responsible for layout, styling, responsiveness, and visual consistency.

Avoid unnecessary complexity and keep styles modular.

---

## JavaScript (ES6+)

JavaScript should be used only when interaction is required.

Prefer simple, readable solutions over clever implementations.

---

## Markdown

Markdown is used for technical documentation and educational content whenever appropriate.

Documentation should remain version-controlled together with the source code.

---

# Approved Development Tools

* Git
* GitHub
* Visual Studio Code
* Node.js (LTS)
* npm

---

# Technologies Under Evaluation

The following technologies may be adopted in the future if they provide a clear benefit:

* TypeScript
* React (only for highly interactive components)
* Astro Content Collections
* Astro Integrations

These technologies are **not part of the initial version** and should not be introduced without prior discussion.

---

# Not Approved for the Initial Version

The following technologies should not be introduced during the first development phase:

* Bootstrap
* Tailwind CSS
* jQuery
* Vue
* Angular

The objective of the first version is to keep the project simple, understandable, and easy to maintain.

---

# General Guidelines

When multiple technical solutions are available:

1. Prefer the simplest solution.
2. Minimize external dependencies.
3. Favor readability over optimization.
4. Keep the project modular.
5. Introduce new technologies only when they solve an actual problem.

Every addition to the technology stack should have a clear justification.
